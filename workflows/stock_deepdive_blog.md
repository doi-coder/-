# Workflow: 주 2회 종목 딥다이브 블로그 리포트 (수요일/토요일)

> 🎯 **북극성 목표 (모든 판단의 기준, 2026-08-10 사장님 확정)**: 이 워크플로우도
> [[economy_daily_reports]]/[[daily_health_topic_report]]와 같은 목표를 공유한다 —
> **블로그 검색 유입을 극대화해서 하루 애드포스트 수익을 점차 늘리는 것.** 다만 이 리포트는
> 하루 3회 도는 뉴스 브리핑과 달리, 종목 하나를 깊게 파는 **에버그린 검색 콘텐츠**로 다른 역할을
> 맡는다 — "오늘 뉴스"가 아니라 "삼성전자 밸류에이션", "테슬라 지금 사도 되나" 같이 시간이
> 지나도 계속 검색되는 키워드를 노린다. 여기서도 어그로 금지·제목-본문 일치 원칙은 동일하게
> 적용된다.

## 왜 만들었나 (2026-08-10, Notion에서 본 개인 투자 리서치 자동화 사례 참고)
사장님이 [Claude Code로 개인 투자 리서치 자동화한 사례](https://puzzle-voice-64f.notion.site/)를
보고, 그 구조 중 우리 블로그에 없던 "종목 단위 딥다이브" 개념을 가져와 만들었다. 원본은 개인
투자 판단용이라 매매신호를 내지 않는 게 원칙이었는데, 우리는 목적이 다르다 — **블로그 독자
유입용 콘텐츠**다. 그래도 "매매신호 금지·출처 필수·숫자는 지어내지 않기" 같은 안전장치는
법적 리스크(투자자문업 미등록 상태에서 매수·매도 권유 시 문제) 때문에 그대로 가져온다.

## 목표
매주 수요일과 토요일 오전 9시(KST), 종목 하나를 골라 (1) 이 회사가 뭐 하는 회사인지, (2) 최근
스토리(실적·이슈 흐름)가 어떻게 바뀌었는지, (3) 지금 가격 흐름을 어떻게 참고하면 되는지 —
세 갈래로 깊게 파헤친 블로그 소재를 PDF(조사 자료)와 초안 텍스트 파일로 만들어 Claude 앱으로
전달한다. 수요일은 국내 종목, 토요일은 해외(주로 미국) 종목을 다룬다.

## ⚠ 반드시 지킬 것 — 안전장치 5가지
[[economy_daily_reports]]의 원칙에 더해, 종목 하나를 깊게 다루는 만큼 아래를 추가로 지킨다:

1. **출처 규칙**: 출처 없는 숫자는 쓰지 않는다. 확인이 안 되면 "확인 필요"라고 남기고, 아무
   URL이나 갖다 붙이지 않는다 — 잘못된 출처 표기가 가장 위험한 실수다.
2. **계산 규칙**: 실적·밸류에이션 수치(PER, 매출 성장률 등)는 WebSearch로 실제 조회된 값만
   쓴다. 직접 암산하거나 추정해서 숫자를 만들어내지 않는다 — 확인 안 되는 계산은 "정확한 수치
   확인 어려움"이라고 솔직히 쓴다.
3. **사실/해석 분리**: 기사에 나온 사실(실적 발표 수치, 발표 일정 등)과 에이전트의 해석·설명을
   섞어 쓰지 않는다. 문단 안에서 "~라고 발표했습니다(사실)" / "이건 ~라는 의미로 볼 수 있어요
   (해설)"처럼 어느 쪽인지 독자가 구분할 수 있게 쓴다.
4. **매매 신호 금지**: "사세요/파세요"는 절대 안 쓴다. "확인해보면 좋은 지표", "이런 상황에서
   흔히 하는 실수" 같은 정보성 톤을 유지한다 (투자자문업 등록 없이 매매 권유 시 법적 문제 —
   [[economy_daily_reports]] 참고).
5. **AI는 1차 스크리닝만**: 이 리포트가 결론을 대신 내려주는 게 아니라, 독자가 스스로 더
   확인해볼 방향을 좁혀주는 자료라는 걸 리포트 안에 명확히 남긴다(면책 문구 포함).

## 언제 실행하나
- `schedule` 기능(클라우드 routine)으로 매주 수요일·토요일 09:00 KST에 자동 실행되도록
  등록한다 (아직 등록 전이면 [[README]] 또는 `schedule` 스킬로 사장님이 직접 등록).
- 사장님이 "이번 주 종목 딥다이브 다시 만들어줘"처럼 수동으로 요청할 때도 같은 절차로 실행한다.

## 공통 실행 절차 (Agent가 할 일)
1. 오늘이 수요일인지 토요일인지 확인해서 `market`을 정한다: 수요일 → `domestic`(국내 종목),
   토요일 → `overseas`(해외 종목, 주로 미국).
2. **종목을 고른다** — 아래 "종목 선정 기준" 절차를 따른다.
3. WebSearch로 고른 종목의 최근 뉴스·실적·사업 구조를 조사한다. 최소 3개 이상의 서로 다른
   출처를 확인한다 (기업 개요 1개 + 최근 이슈/실적 관련 1개 이상 + 밸류에이션 참고 자료 1개
   이상).
4. **제목 후보 2~3개**를 뽑고 하나를 "추천 제목"으로 고른다 (아래 "제목·키워드 선정 기준"
   참고).
5. 조사한 내용을 아래 JSON 형식으로 정리해서
   `.tmp/stock_deepdive_data/<market>_YYYY-MM-DD.json`에 저장한다:
   ```json
   {
     "report_type": "stock_deepdive",
     "report_date": "2026-08-12",
     "market": "domestic",
     "slot_label": "삼성전자(005930) · 수요일 국내 종목 딥다이브",
     "stock_name": "삼성전자",
     "ticker": "005930",
     "selection_reason": "이번 주 실적 발표 + 검색 관심도 상승 (근거 구체적으로)",
     "headline": "오늘 다룰 종목 한 줄 요약",
     "sections": [
       {"heading": "기업 해독기 — 이 회사 뭐 하는 회사인가", "body": "..."},
       {"heading": "스토리 리더 — 요즘 이 회사 어때", "body": "..."},
       {"heading": "가격 판독기 — 지금 흐름 참고하기", "body": "..."}
     ],
     "sources": ["기사/자료 제목 (매체명) - URL", "..."],
     "suggested_titles": ["네이버 블로그 제목 후보 2~3개"],
     "recommended_title": "suggested_titles 중 추천 1개",
     "recommended_keyword": "recommended_title의 핵심 검색 키워드 (예: '삼성전자 밸류에이션')",
     "search_intent": "이 키워드를 검색하는 사람들이 실제로 뭘 원해서 검색했을지",
     "target_analysis": "타겟 독자 분석 — 구체적 상황(예: '삼성전자 보유 중인데 지금 상황이 궁금한 3040 직장인')",
     "keyword_analysis": "키워드를 고른 근거 — 경쟁도·시의성 데이터 기반으로",
     "data_note": "선택 사항 — 조사가 부족했다면 그 사실을 적는다"
   }
   ```
6. `python tools/economy_report_builder.py <json경로> .tmp/reports/stock_deepdive_<market>_<날짜>.pdf`
   를 실행한다 (`report_type: "stock_deepdive"`로 인식됨).
7. `recommended_title`에 대해 블로그 초안을 작성해서
   `.tmp/reports/stock_deepdive_<market>_<날짜>_draft.txt`에 저장한다 (아래 "블로그 초안 작성
   지침" 참고).
8. 생성된 PDF와 초안 txt 파일 **둘 다** 채팅 응답에 **직접 첨부**해서 전달하고, 푸시 알림도
   보낸다.
9. **`.tmp/stock_deepdive_history.json`을 갱신**한다 — 오늘 다룬 `stock_name`과 `report_date`를
   추가한다(파일이 없으면 새로 만든다, 형식은 `[{"stock_name": "삼성전자", "report_date":
   "2026-08-12", "market": "domestic"}, ...]`). 다음 회차 종목 선정 시 이 파일로 최근 8주 내
   중복 종목을 피한다.
10. 결과를 사장님께 짧게 보고한다: 오늘 다룬 종목 + 추천 제목 + PDF·초안 첨부. 조사가 부실했다면
    그 사실도 솔직히 알린다.

## 종목 선정 기준
1. **`.tmp/stock_deepdive_history.json`을 먼저 확인**해서 최근 8주(약 16회차) 내 다룬 종목은
   피한다. 파일이 없거나 비어 있으면 그냥 진행한다.
2. WebSearch로 이번 주 `market`(국내/해외) 종목 중 아래에 해당하는 후보를 3~5개 추린다:
   - 최근 1주일 내 실적 발표·큰 뉴스(신제품, 인수합병, 정책 이슈 등)가 있었던 종목 — 시의성
   - 널리 알려진 대형주 우선 — 처음 들어보는 소형주보다 검색 가능성이 높음
   - 국내 종목은 코스피/코스닥 시가총액 상위권 위주, 해외는 미국 빅테크·널리 알려진 우량주 위주
3. 후보마다 `tools/naver_blog_search.py`의 `keyword_saturation("<종목명> 분석")` 같은 키워드로
   경쟁도를 확인한다. 극단적으로 이미 포화된 키워드(예: 매주 나오는 초대형주만 계속 다루면
   레드오션)보다, 시의성 있는 이슈가 있으면서도 적당히 다뤄지고 있는 종목을 우선한다.
4. 위 기준으로 후보 하나를 최종 선정하고, `selection_reason`에 왜 이 종목을 골랐는지 구체적으로
   남긴다 (예: "이번 주 2분기 실적 발표 + 반도체 업황 뉴스로 검색 관심도 상승").

## 제목·키워드 선정 기준
[[economy_daily_reports]]와 같은 원칙을 따르되, 종목 딥다이브 특유의 검색 패턴을 우선한다:
- "OO 분석", "OO 밸류에이션", "OO 지금 사도 되나", "OO 전망" 같이 종목명 + 판단 보조 키워드
  조합을 우선한다 (직접 매수·매도를 답해주는 게 아니라 "참고할 정보를 준다"는 톤 유지).
- `keyword_saturation()`으로 확인한 경쟁도와, `selection_reason`에서 정리한 시의성 근거를
  `keyword_analysis`에 반영한다.
- 이 리포트는 에버그린 콘텐츠 성격이 강하므로, 오늘 하루만 유효한 표현("오늘", "속보")보다
  당분간 계속 검색돼도 어색하지 않은 제목을 우선한다.

## 블로그 초안 작성 지침
[[economy_daily_reports]]의 초안 지침과 동일한 형식·분량(800~1200자, 1인칭 블로그 말투,
키워드 배치, 베끼지 않기)을 따르되, 아래를 추가로 지킨다:
- 세 섹션(기업 해독기/스토리 리더/가격 판독기)을 순서대로 재구성하되, 소제목은 초안에서는
  자연스러운 블로그 문장으로 풀어써도 된다 (JSON의 heading을 그대로 복붙하지 않는다).
- "가격 판독기" 내용을 초안에 옮길 때 특히 조심한다 — 위 안전장치 4번(매매 신호 금지)을 다시
  한번 확인하고, 매수·매도를 권하는 뉘앙스가 들어가지 않았는지 스스로 검토한 뒤 저장한다.
- 마무리에 짧은 면책 문구를 남긴다: "이 글은 정보 제공 목적이며 투자 추천이 아닙니다. 투자
  판단과 책임은 본인에게 있습니다."

## 결과물 확인 위치
- PDF: `.tmp/reports/stock_deepdive_<market>_YYYY-MM-DD.pdf`
- 블로그 초안: `.tmp/reports/stock_deepdive_<market>_YYYY-MM-DD_draft.txt`
- 조사 데이터(JSON): `.tmp/stock_deepdive_data/<market>_YYYY-MM-DD.json`
- 종목 이력(중복 방지용): `.tmp/stock_deepdive_history.json`

## 실패했을 때 대응 원칙
- WebSearch 결과가 부족하면 없는 내용을 채우지 말고 `data_note`에 그 사실을 적는다. 조사가
  약하면 후보 종목을 바꾸는 것도 고려한다(3~5개 후보 중 두 번째로 넘어가기).
- PDF 생성이 에러로 실패하면(예: `report_type`을 못 찾음) 에러 내용을 쉬운 말로 설명한다 —
  `tools/economy_report_builder.py`의 `REPORT_META`에 `"stock_deepdive"` 키가 있는지 먼저 확인.
- 같은 원인의 실패가 반복되면 이 문서와 `economy_report_builder.py`를 업데이트한다.

## 사용하는 Tool
- `tools/economy_report_builder.py` — JSON을 PDF로 조립. `REPORT_META["stock_deepdive"]`로
  이 리포트 전용 제목·면책 문구가 등록돼 있다. [[economy_daily_reports]]와 같은 도구를 그대로
  재사용한다(새로 안 만듦).
- `tools/naver_blog_search.py`의 `keyword_saturation()` — 종목명 키워드 경쟁도 확인.
- WebSearch — 종목 뉴스·실적·사업구조 조사 (별도 API 키 불필요).

## 알려진 한계 (사장님이 알아야 하는 것)
- 이 리포트는 투자자문이 아니라 정보 정리 자료다. 매매신호를 내지 않는 원칙을 지키지만, 그래도
  블로그에 옮겨 쓸 때 면책 문구를 유지하는 게 안전하다.
- 실제 재무제표 기반 정밀 밸류에이션(DCF 등)을 직접 계산하지는 않는다 — WebSearch로 조회되는
  공개된 컨센서스·참고 지표만 인용한다. 더 정교한 계산이 필요해지면 별도 계산 도구 연동을
  사장님과 상의 후 추가한다.
- 종목 선정은 시가총액·시의성 같은 정성적 기준이라, 실제 검색량 데이터(네이버 검색광고 API
  미연동 — [[economy_daily_reports]] 참고)로 검증된 건 아니다.
- 초안은 시작점이지 완성본이 아니다 — 특히 "가격 판독기" 섹션은 발행 전 사장님이 한 번 더
  훑어보길 권장한다.
