# Workflow: 매일 3회 경제 블로그 소재 리포트 (국내장 / 실용정보 / 미국장)

## 목표
매일 세 번 — 아침 6시, 낮 2시, 저녁 6시반(KST) — 그 시점까지 나온 실제 뉴스를 조사해서,
주식 초보자("주린이") 눈높이에 맞는 해설과 참고 방향을 담은 PDF 리포트를 만들어 Claude 앱으로
전달한다. 사장님은 이 PDF를 참고해서 네이버 블로그 글을 작성한다.

건강 리포트([[daily_health_topic_report]])와 다른 점: 건강 리포트는 데이터랩/유튜브처럼 고정된
API로 숫자를 가져오지만, 이 리포트는 그날그날의 실제 뉴스를 다뤄야 하므로 정해진 API가 없다.
그래서 실행하는 에이전트 본인이 WebSearch로 직접 조사하고 해설을 작성한 뒤, 그 결과를 JSON으로
정리해서 `tools/economy_report_builder.py`에 넘겨 PDF로 조립한다. PDF 전달 방식(이메일 대신 채팅
직접 첨부)은 건강 리포트와 동일하다.

## ⚠ 반드시 지킬 것 — 지어내지 않기
이 리포트는 사람이 검증하지 않은 실시간 조사 내용을 담는다. 다음을 반드시 지킨다:
- WebSearch로 실제 검색한 내용만 쓴다. 검색 결과가 부족하면 "오늘은 조사된 내용이 적습니다"라고
  솔직히 쓰고 다른 소재로 넘어간다 — 그럴듯하게 지어내지 않는다.
- 각 섹션에서 다룬 뉴스는 반드시 `sources`에 기사 제목과 링크를 남긴다. 출처 없는 정보는 쓰지 않는다.
- "투자 방향 참고" 섹션은 특정 종목의 매수·매도를 지시하는 어조를 쓰지 않는다. "이런 뉴스가 나오면
  초보자가 흔히 하는 실수", "확인해보면 좋은 지표" 같은 정보성 톤을 유지한다. (투자자문업 등록 없이
  특정 종목 매매를 권유하면 법적 문제가 될 수 있음 — [[naver_blog_ad_strategy]] 참고)

## 언제 실행하나
- `schedule` 기능(클라우드 routine)으로 매일 3번 자동 실행되도록 등록되어 있음:
  - 06:00 KST — 국내장 (`domestic_market`)
  - 14:00 KST — 실용정보 (`practical_info`)
  - 18:30 KST — 미국장 (`us_market`)
- 사장님이 "오늘 국장 리포트 다시 만들어줘"처럼 수동으로 요청할 때도 같은 절차로 실행한다.

## 공통 실행 절차 (Agent가 할 일)
1. 어떤 슬롯인지 확인한다 (아래 슬롯별 지침 참고). report_type 값을 정확히 맞춘다:
   `domestic_market` / `practical_info` / `us_market`.
2. **주제를 고른다** — 아무 뉴스나 다루지 않고, 아래 "주제 선정 기준" 절차를 따라 독자가 실제
   검색할 만한 주제를 먼저 정한다.
3. WebSearch로 고른 주제에 대한 오늘자(또는 최신) 뉴스를 조사한다. 최소 2~3개의 서로 다른
   출처를 확인한다.
4. 조사한 내용을 아래 JSON 형식으로 정리해서 `.tmp/economy_data/<report_type>_YYYY-MM-DD.json`에
   저장한다:
   ```json
   {
     "report_type": "domestic_market",
     "report_date": "2026-08-06",
     "slot_label": "아침 6시 브리핑",
     "headline": "오늘 한 줄 요약",
     "sections": [
       {"heading": "오늘의 기업/시장 소식", "body": "..."},
       {"heading": "주린이를 위한 해설", "body": "..."},
       {"heading": "투자 방향 참고", "body": "..."}
     ],
     "sources": ["기사 제목 (매체명) - URL", "..."],
     "suggested_titles": ["네이버 블로그에 올릴 때 쓸 SEO 제목 후보 2~3개"],
     "data_note": "선택 사항 — 검색 결과가 부족했다면 여기에 그 사실을 적는다"
   }
   ```
   (`practical_info` 슬롯은 세 번째 섹션 heading을 "직장인 활용법"으로 쓴다.)
5. `python tools/economy_report_builder.py <json경로> .tmp/reports/economy_<report_type>_<날짜>.pdf`
   를 실행한다 (python이 없으면 python3). `pip install -r requirements.txt`가 안 되어 있으면 먼저
   실행한다.
6. 생성된 PDF를 이 채팅 응답에 **직접 첨부**해서 전달하고, 푸시 알림도 보낸다.
7. 결과를 사장님께 짧게 보고한다: 오늘 헤드라인 한 줄 + PDF 첨부. 조사가 부실했다면 그 사실도
   솔직히 알린다.

## 주제 선정 기준 — 독자 니즈 반영 (검색유입·구독자 극대화가 목표)
이 리포트의 최종 목적은 아무 정보 전달이 아니라, 사장님 블로그의 **검색유입과 충성 구독자를
늘려서 애드포스트 수익을 극대화**하는 것이다. 경제 블로그 독자들이 이런 글을 찾는 이유는
대체로 네 가지다: (1) 바로 써먹는 실전 정보, (2) 어려운 뉴스를 쉽게 풀어주는 해설, (3) 시의성,
(4) "나도 할 수 있다"는 동질감·참고자료. 주제를 고를 때 이 네 가지 중 최소 하나에 뚜렷하게
해당하는지 자문한다.

### 실용정보(14:00) 슬롯 — 데이터로 주제 검증
1. `tools/naver_trend.py`의 `get_rising_keywords_by_segment(categories=...)`를 아래 카테고리로
   호출해서 최근 검색 관심도가 오르고 있는 분야를 확인한다 (이 함수는 이미 임의의 `categories`
   딕셔너리를 받게 만들어져 있으므로 새 파일을 만들 필요 없음):
   ```python
   ECONOMY_PRACTICAL_CATEGORIES = {
       "대출/전세자금": ["전세자금대출", "신용대출한도", "중도상환수수료"],
       "청약/부동산정책": ["청약통장", "특별공급", "생애최초주택"],
       "절세/연말정산": ["연말정산", "종합소득세", "세액공제"],
       "카드혜택": ["신용카드혜택", "체크카드추천", "카드전월실적"],
       "앱테크": ["앱테크", "만보기적립", "리워드앱"],
       "부업/부수입": ["부업추천", "재택부업", "부수입만들기"],
       "정부지원금": ["청년지원금", "정부지원금신청", "근로장려금"],
   }
   ```
2. 상승률이 높은 카테고리 중 `tools/naver_blog_search.py`의 `keyword_saturation()`으로 블로그
   경쟁도를 확인해서, 경쟁이 너무 치열하지 않은(레드오션이 아닌) 키워드를 우선한다.
3. 그렇게 고른 키워드로 오늘의 실제 뉴스를 WebSearch로 조사한다. 오늘 새 뉴스가 없으면 그
   키워드를 evergreen 정보(카드 혜택, 앱테크 등)로 다룬다.

### 국내장(06:00) / 미국장(18:30) 슬롯 — 뉴스 자체가 시의성이라 판단 기준으로 대체
시장 뉴스는 매일 바뀌어서 고정 키워드 트렌드로 미리 고를 수 없다. 오늘 여러 뉴스 후보 중 아래
기준으로 우선순위를 정한다:
- 널리 알려진 기업/이슈일수록 우선 (실제로 검색될 가능성이 높음)
- "이게 나한테 무슨 의미인지"를 분명히 설명할 수 있는 이슈 우선 (막연한 시황 나열 X)
- 오늘 자로 시의성이 뚜렷한 것 (몇 주 전부터 알려진 얘기 반복 X)

## 슬롯별 조사 지침

### 06:00 국내장 (`domestic_market`)
- 조사 대상: 간밤 미국 증시 마감 결과가 국내 시장에 줄 영향, 오늘 코스피/코스닥 관련 주요 기업
  뉴스(실적, 공시, 신제품 등), 오늘 예정된 이벤트(실적 발표, 금통위 등).
- "주린이를 위한 해설" 섹션에서는 나온 용어(공시, 실적 컨센서스 등)를 쉬운 말로 풀어준다.

### 14:00 실용정보 (`practical_info`)
- 조사 대상: 오늘 새로 나온 정책/대출/청약/세금 관련 뉴스를 우선 검색한다.
- 오늘 마땅한 새 뉴스가 없으면: 카드 혜택, 앱테크, 부수입/부업 정보처럼 시기를 안 타는 주제로
  대체해도 된다 (사장님이 사전에 승인한 대체 규칙).
- "직장인 활용법" 섹션은 반드시 포함한다 — 일반 직장인이 오늘 당장 뭘 하면 되는지 구체적으로.

### 18:30 미국장 (`us_market`)
- 조사 대상: 그날 낮~저녁까지 나온 미국 시장 관련 뉴스(선물 동향, 전일 마감 이후 발표된 실적/이슈,
  오늘 밤 발표 예정인 경제지표·실적 일정).
- 개장(서머타임 기준 밤 10시반, 겨울엔 밤 11시반)까지 몇 시간 남은 시점이므로, "오늘 밤 지켜볼
  포인트를 미리 정리해준다"는 예고편 톤을 유지한다.

## 결과물 확인 위치
- PDF: `.tmp/reports/economy_<report_type>_YYYY-MM-DD.pdf`
- 조사 데이터(JSON): `.tmp/economy_data/<report_type>_YYYY-MM-DD.json`

## 실패했을 때 대응 원칙
- WebSearch 결과가 너무 적거나 신뢰하기 어려우면, 없는 내용을 채우지 말고 `data_note`에 그 사실을
  적고 다룰 수 있는 만큼만 다룬다. 실행 자체를 멈추지 않는다.
- PDF 생성(`economy_report_builder.py`) 자체가 에러로 실패하면 에러 내용을 쉬운 말로 사장님께
  설명한다. 같은 원인의 실패가 반복되면 이 문서와 `economy_report_builder.py`를 업데이트해서
  다음에는 자동으로 처리되게 한다.

## 사용하는 Tool
- `tools/economy_report_builder.py` — JSON 데이터를 받아 PDF로 조립. `python tools/economy_report_builder.py`만
  인자 없이 실행하면 샘플 데이터로 테스트 가능.
- WebSearch — 슬롯별 조사 대상 뉴스 검색 (별도 API 키 필요 없음, 에이전트 내장 기능).

## 알려진 한계 (사장님이 알아야 하는 것)
- 이 리포트는 투자자문이 아니라 정보 정리 자료다. PDF 하단에 면책 문구가 자동으로 들어가지만,
  블로그에 옮겨 쓸 때도 "투자 판단은 본인 책임" 같은 문구를 유지하는 게 안전하다.
- 실시간 웹 검색 기반이라, 검색 엔진에 아직 안 올라온 아주 최신 속보는 놓칠 수 있다.
- 18:30 미국장 리포트는 실제 개장 2~3시간 전이라 "예고편" 성격이다 — 개장 직전 최신 상황과는
  다를 수 있음을 사장님도 감안해야 한다.
