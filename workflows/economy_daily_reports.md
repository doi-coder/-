# Workflow: 매일 3회 경제 블로그 소재 리포트 (국내장 / 실용정보 / 미국장)

> 🎯 **북극성 목표 (모든 판단의 기준, 2026-08-10 사장님 확정)**: 이 워크플로우의 모든 선택 —
> 주제, 카테고리 로테이션, 제목, 키워드, 초안 문체 — 은 전부 하나의 목표를 위해 존재한다:
> **블로그 검색 유입을 극대화해서 하루 애드포스트 수익을 점차 늘리는 것.** 구체적으로 네
> 가지 기준으로 판단한다: (1) 그날그날 검색량이 높은 관련 키워드를 고르되, 어제·그제와
> 겹치지 않는 소재로 매일 다른 검색 니즈를 반영한다. (2) 제목은 어그로가 아니라 본문 내용과
> 정확히 일치해야 하고, 거짓·과장 정보를 지어내지 않는다. (3) 초안 하나하나가 실제 검색
> 유입으로 이어지도록 쓴다. (4) 이 모든 게 쌓여서 하루 애드포스트 수익을 점차 늘리는 게
> 최종 목표다. 정보가 정확하고 유용한 것만으로는 부족하다 — 실제로 사람들이 검색해서
> 들어오고, 다시 찾아오게 만드는 게 최우선이다. 아래 각 섹션에서 이 목표를 반복해서 언급하는
> 건 강조를 위한 게 아니라, 실제로 매 판단 지점마다 이 기준으로 돌아가야 하기 때문이다.
> [[daily_health_topic_report]]도 같은 목표를 공유한다.

## 목표
매일 세 번 — 아침 6시, 낮 2시, 저녁 6시반(KST) — 그 시점까지 나온 실제 뉴스를 조사해서,
주식 초보자("주린이") 눈높이에 맞는 해설과 참고 방향을 담은 PDF 리포트를 만들어 Claude 앱으로
전달한다. 사장님은 이 PDF를 참고해서 네이버 블로그 글을 작성한다.

건강 리포트([[daily_health_topic_report]])와 다른 점: 건강 리포트는 데이터랩/유튜브처럼 고정된
API로 숫자를 가져오지만, 이 리포트는 그날그날의 실제 뉴스를 다뤄야 하므로 정해진 API가 없다.
그래서 실행하는 에이전트 본인이 WebSearch로 직접 조사하고 해설을 작성한 뒤, 그 결과를 JSON으로
정리해서 `tools/economy_report_builder.py`에 넘겨 PDF로 조립한다. PDF 전달 방식(이메일 대신 채팅
직접 첨부)은 건강 리포트와 동일하다.

## 타겟 독자 — 국장·미장·부업에 관심 있는 3040 직장인 (2026-08-09 확정)
이 리포트 전체의 타겟은 **국내·미국 주식에 관심 있고, 본업 외에 부업으로 추가 수입을 만들고
싶어하는 30~40대 직장인**이다. 주제·키워드·문체를 고를 때마다 "이 사람이면 뭐라고 검색할까,
뭘 궁금해할까"를 기준으로 삼는다. 전문 트레이더나 은퇴한 전업 투자자가 아니다.

- **투자 성향**: 전업 투자자가 아니라 본업이 있는 상태에서 여유자금으로 굴리는 "생활 투자자".
  단타·파생상품보다 배당, ISA, 연금저축 같은 장기·절세 관점에 관심이 많고, "이 뉴스가 내 계좌에
  어떤 의미인지"를 알고 싶어한다.
- **관심사**: 국장/미장 투자, 부업·부수입, 대출/전세, 청약·내 집 마련, 절세, 카드·정부 혜택 —
  아래 "주제 선정 기준"의 4가지 니즈를 이 페르소나 관점에서 구체화한다.
- **검색 의도**: "OO 뜻", "OO 하는 법"처럼 초보자가 개념을 확인하는 검색과, "OO 후기", "OO
  방법", "직장인 OO", "월급 외 OO"처럼 바로 실행할 정보를 찾는 검색을 함께 한다. 전문
  트레이더용 용어(옵션 그릭스, 선물 스프레드 등)보다 이 타겟이 실제로 검색창에 치는 생활 밀착형
  표현을 우선한다.
- **슬롯별 반영**:
  - 국내장/미국장: "이게 내 월급·내 계좌에 어떤 의미인지"를 꼭 짚어준다. 전문 트레이딩 전략보다
    배당·ISA·연금저축·장기 적립 관점의 해설을 우선한다.
  - 실용정보: 이미 카테고리 로테이션(대출/청약/절세/카드혜택/앱테크/부업/정부지원금) 자체가
    이 타겟에 맞춰져 있다. 특히 부업/부수입 배정일은 이 타겟의 핵심 관심사이므로, 막연한 목록이
    아니라 실제로 오늘 당장 해볼 수 있는 방법·예상 수입 범위처럼 구체적으로 쓴다.
  - 제목·키워드: 위 검색 의도 패턴("OO 뜻/방법", "직장인 OO", "월급 외 OO")에 맞는 키워드를
    `제목·키워드 선정 기준`에서 우선순위로 삼는다.
  - 초안 어조: 같은 3040 직장인이 옆에서 얘기해주는 느낌으로 — "저도 회사 다니면서 ~", "퇴근하고
    ~" 같은 공감대 표현을 자연스럽게 섞는다 (`블로그 초안 작성 지침` 참고).

## ⚠ 반드시 지킬 것 — 지어내지 않기
이 리포트는 사람이 검증하지 않은 실시간 조사 내용을 담는다. 다음을 반드시 지킨다:
- WebSearch로 실제 검색한 내용만 쓴다. 검색 결과가 부족하면 "오늘은 조사된 내용이 적습니다"라고
  솔직히 쓰고 다른 소재로 넘어간다 — 그럴듯하게 지어내지 않는다.
- 각 섹션에서 다룬 뉴스는 반드시 `sources`에 기사 제목과 링크를 남긴다. 출처 없는 정보는 쓰지 않는다.
- "투자 방향 참고" 섹션은 특정 종목의 매수·매도를 지시하는 어조를 쓰지 않는다. "이런 뉴스가 나오면
  초보자가 흔히 하는 실수", "확인해보면 좋은 지표" 같은 정보성 톤을 유지한다. (투자자문업 등록 없이
  특정 종목 매매를 권유하면 법적 문제가 될 수 있음 — [[naver_blog_ad_strategy]] 참고)

## 언제 실행하나
- `schedule` 기능(클라우드 routine)으로 매일 3번 자동 실행되도록 등록되어 있음:
  - 06:00 KST — 국내장 (`domestic_market`)
  - 14:00 KST — 실용정보 (`practical_info`)
  - 18:30 KST — 미국장 (`us_market`)
- 사장님이 "오늘 국장 리포트 다시 만들어줘"처럼 수동으로 요청할 때도 같은 절차로 실행한다.

## 공통 실행 절차 (Agent가 할 일)
1. 어떤 슬롯인지 확인한다 (아래 슬롯별 지침 참고). report_type 값을 정확히 맞춘다:
   `domestic_market` / `practical_info` / `us_market`.
2. **주제를 고른다** — 아무 뉴스나 다루지 않고, 아래 "주제 선정 기준" 절차를 따라 독자가 실제
   검색할 만한 주제를 먼저 정한다.
3. WebSearch로 고른 주제에 대한 오늘자(또는 최신) 뉴스를 조사한다. 최소 2~3개의 서로 다른
   출처를 확인한다.
4. **제목 후보 2~3개를 뽑고, 그중 하나를 "추천 제목"으로 고른다.** 추천 제목에 대해서는
   검색 의도(`search_intent`)·타겟 독자(`target_analysis`)·키워드 선정 근거(`keyword_analysis`)를
   구체적으로 써둔다 (아래 "제목·키워드 선정 기준" 절차 참고).
5. 조사한 내용을 아래 JSON 형식으로 정리해서 `.tmp/economy_data/<report_type>_YYYY-MM-DD.json`에
   저장한다:
   ```json
   {
     "report_type": "domestic_market",
     "report_date": "2026-08-06",
     "slot_label": "아침 6시 브리핑",
     "headline": "오늘 한 줄 요약",
     "sections": [
       {"heading": "오늘의 기업/시장 소식", "body": "..."},
       {"heading": "주린이를 위한 해설", "body": "..."},
       {"heading": "투자 방향 참고", "body": "..."}
     ],
     "sources": ["기사 제목 (매체명) - URL", "..."],
     "suggested_titles": ["네이버 블로그에 올릴 때 쓸 SEO 제목 후보 2~3개"],
     "recommended_title": "suggested_titles 중 이번 회차에 가장 추천하는 제목 1개",
     "recommended_keyword": "recommended_title의 핵심 검색 키워드 (예: '전세자금대출 한도')",
     "search_intent": "이 키워드를 검색하는 사람들이 실제로 뭘 원해서 검색했을지",
     "target_analysis": "타겟 독자 분석 — 연령·상황을 구체적으로 (예: '전세 재계약을 앞둔 2030 직장인')",
     "keyword_analysis": "이 키워드를 고른 근거 — 블로그 경쟁도·검색 관심도 등 데이터 기반으로",
     "data_note": "선택 사항 — 검색 결과가 부족했다면 여기에 그 사실을 적는다"
   }
   ```
   (`practical_info` 슬롯은 세 번째 섹션 heading을 "직장인 활용법"으로 쓴다.)
6. `python tools/economy_report_builder.py <json경로> .tmp/reports/economy_<report_type>_<날짜>.pdf`
   를 실행한다 (python이 없으면 python3). `pip install -r requirements.txt`가 안 되어 있으면 먼저
   실행한다.
7. **`recommended_title` 하나에 대해서만 블로그 초안을 작성**해서
   `.tmp/reports/economy_<report_type>_<날짜>_draft.txt`에 저장한다 (아래 "블로그 초안 작성
   지침" 참고). 파일 맨 위에 `search_intent`/`target_analysis`/`keyword_analysis`를 요약한
   분석 블록을 먼저 적고, 그 아래에 실제 초안을 쓴다. 나머지 제목 후보는 초안을 쓰지 않는다 —
   참고용 대안으로만 PDF에 남긴다.
8. 생성된 PDF와 초안 txt 파일 **둘 다** 이 채팅 응답에 **직접 첨부**해서 전달하고, 푸시 알림도
   보낸다.
9. 결과를 사장님께 짧게 보고한다: 오늘 헤드라인 한 줄 + 추천 제목 + PDF·초안 첨부. 조사가
   부실했다면 그 사실도 솔직히 알린다.

## 주제 선정 기준 — 독자 니즈 반영 (하루 방문자 수 극대화가 목표)
이 리포트의 최종 목적은 아무 정보 전달이 아니라, 사장님 블로그의 **하루 방문자 수를 늘려서
애드포스트 수익을 극대화**하는 것이다(북극성 목표 참고). 독자는 위 "타겟 독자"에서 정한
3040 직장인이고,
이들이 이런 글을 찾는 이유는 대체로 네 가지다: (1) 바로 써먹는 실전 정보(부업·절세·혜택),
(2) 어려운 뉴스를 쉽게 풀어주는 해설("내 계좌엔 무슨 의미"), (3) 시의성, (4) "나도 할 수
있다"는 동질감·참고자료(같은 직장인 관점). 주제를 고를 때 이 네 가지 중 최소 하나에 뚜렷하게
해당하는지 자문한다.

### 실용정보(14:00) 슬롯 — 데이터로 주제 검증
> ⚠ **왜 요일 고정 방식으로 바뀌었나 (2026-08-09 발견된 문제)**: 예전에는 7개 카테고리 중
> 상승률이 가장 높은 것만 골랐다. 그런데 "정부지원금"(근로장려금 조기지급) 카테고리가 며칠
> 연속으로 검색 관심도 1위를 차지하면서, 실제로 3일 내내 같은 주제만 나가는 문제가 생겼다.
> 뉴스가 부족해서가 아니라 — 그 카테고리에 계속 새 뉴스가 나오면서 "1위" 자리를 안 내줬기
> 때문. 그래서 지금은 요일별로 다룰 카테고리를 미리 고정해서 로테이션시키고, 그 카테고리
> 안에서만 상승률/경쟁도를 비교해 구체적 키워드를 고르는 방식으로 바꿨다.

1. **오늘(KST 기준) 요일에 배정된 카테고리를 먼저 정한다.** 상승률과 무관하게 이 표를 그대로
   따른다:

   | 요일 | 카테고리 |
   |---|---|
   | 월 | 정부지원금 |
   | 화 | 대출/전세자금 |
   | 수 | 절세/연말정산 |
   | 목 | 카드혜택 |
   | 금 | 앱테크 |
   | 토 | 부업/부수입 |
   | 일 | 청약/부동산정책 |

   ```python
   ECONOMY_PRACTICAL_CATEGORIES = {
       "대출/전세자금": ["전세자금대출", "신용대출한도", "중도상환수수료"],
       "청약/부동산정책": ["청약통장", "특별공급", "생애최초주택"],
       "절세/연말정산": ["연말정산", "종합소득세", "세액공제"],
       "카드혜택": ["신용카드혜택", "체크카드추천", "카드전월실적"],
       "앱테크": ["앱테크", "만보기적립", "리워드앱"],
       "부업/부수입": ["부업추천", "재택부업", "부수입만들기"],
       "정부지원금": ["청년지원금", "정부지원금신청", "근로장려금"],
   }
   ```
2. `tools/naver_trend.py`의 `get_rising_keywords_by_segment(categories=...)`로 **오늘 배정된
   카테고리 안의** 구체적 키워드 중 상승률이 높은 걸 확인하고, `tools/naver_blog_search.py`의
   `keyword_saturation()`으로 경쟁도까지 확인해서 다룰 키워드를 좁힌다.
3. 그렇게 고른 키워드로 오늘의 실제 뉴스를 WebSearch로 조사한다. 오늘 배정된 카테고리 안에서
   새 뉴스가 없으면, 그 카테고리를 벗어나지 말고 evergreen 정보로 다룬다 (예: 앱테크 배정일인데
   새 뉴스가 없으면 "요즘 뜨는 앱테크 앱 비교"처럼).
4. **예외는 딱 하나 — 배정 안 된 카테고리에서 정말 크고 시급한 뉴스**(정책 발표 당일, 마감
   임박 등)가 터졌을 때만 그날 배정을 깨고 다뤄도 된다. 이 경우 `data_note`에 "오늘은 예외적으로
   배정된 카테고리(OO) 대신 XX를 다뤘습니다: (이유)"라고 반드시 남긴다.

### 국내장(06:00) / 미국장(18:30) 슬롯 — 뉴스 자체가 시의성이라 판단 기준으로 대체
시장 뉴스는 매일 바뀌어서 고정 키워드 트렌드로 미리 고를 수 없다. 오늘 여러 뉴스 후보 중 아래
기준으로 우선순위를 정한다:
- 널리 알려진 기업/이슈일수록 우선 (실제로 검색될 가능성이 높음)
- "이게 나한테 무슨 의미인지"를 분명히 설명할 수 있는 이슈 우선 (막연한 시황 나열 X)
- 오늘 자로 시의성이 뚜렷한 것 (몇 주 전부터 알려진 얘기 반복 X)

## 제목·키워드 선정 기준
제목·키워드는 방문자 수를 결정하는 가장 직접적인 지점이다 — 아무리 내용이 좋아도 검색에서
안 걸리면 방문자로 이어지지 않는다. `suggested_titles`를 뽑을 때, 그냥 그럴듯한 제목이 아니라
사람들이 실제로 네이버에 검색해볼 만한 키워드가 들어간 제목을 우선한다. 이 리포트에는 실제 월간 검색량을 조회하는 API가 연동돼 있지
않으므로(네이버 검색광고 API는 별도 신청이 필요 — [알려진 한계](#알려진-한계-사장님이-알아야-하는-것)
참고), 아래 두 가지 신호를 대신 참고 지표로 쓴다:

1. **경쟁도 확인** — 제목 후보마다 핵심 키워드를 뽑아 `tools/naver_blog_search.py`의
   `keyword_saturation(keyword)`를 돌려 `total_count`(이미 나온 글 수)를 확인한다. 너무 적으면
   아무도 안 찾는 키워드일 수 있고, 너무 많으면 이미 레드오션이다 — 극단적으로 낮거나
   (검색 자체가 없을 정도) 극단적으로 높은 키워드는 피하고, 적당히 다뤄지고 있으면서도 오늘
   다루는 뉴스처럼 시의성이 있는 키워드를 우선한다.
2. **관심도 신호** — `practical_info` 슬롯은 앞서 "주제 선정" 단계에서 이미 확인한
   `get_rising_keywords_by_segment` 상승률을 그대로 재사용한다. `domestic_market`/`us_market`
   슬롯은 별도 트렌드 API 없이, "널리 보도되고 있는 정도"(WebSearch 결과 수·주요 매체 여부)를
   관심도 대용 지표로 쓴다.
3. **검색 의도 패턴 반영** — "타겟 독자"에서 정한 3040 직장인이 실제로 검색창에 칠 법한 패턴을
   제목 후보에 최소 하나는 반영한다: "OO 뜻"/"OO 하는 법"(개념 확인형), "직장인 OO"/"월급 외
   OO"/"OO 후기"(실행형). 전문 트레이더용 어휘보다 이 패턴을 우선한다.
4. 위 신호들을 참고해서 `suggested_titles` 중 하나를 `recommended_title`로 고르고, 그 제목의
   핵심 키워드를 `recommended_keyword`로 남긴다. 고르는 기준 우선순위: (1) 오늘 실제로 다룬
   뉴스/정보와 직접 연결되는 키워드일 것(막연한 키워드 금지), (2) 극단적 레드오션이 아닐 것,
   (3) 3040 직장인의 검색 의도 패턴에 맞을 것, (4) `practical_info`는 상승률이 뚜렷한 쪽을 우선.
5. `recommended_title`에 대해 세 가지를 구체적으로 써서 JSON에 남긴다 (건강 리포트
   [[daily_health_topic_report]]와 같은 형식):
   - `search_intent`: 이 키워드를 검색하는 사람들이 실제로 뭘 원해서 검색했을지
   - `target_analysis`: 타겟 독자 분석 — "타겟 독자"의 3040 직장인 안에서도 오늘 이 주제에
     특히 해당하는 구체적 상황(예: "전세 재계약 앞둔 맞벌이 부부")
   - `keyword_analysis`: 이 키워드를 고른 근거 — 위 1~3번 신호(경쟁도·관심도·검색 의도 패턴)를
     데이터 기반으로 요약

## 블로그 초안 작성 지침
초안의 역할은 정보 전달이 아니라 "검색해서 들어온 사람이 끝까지 읽고, 다음에도 이 블로그를
찾아오게 만드는 것"이다(북극성 목표 참고) — 그래서 도입부 후킹과 키워드 배치가 특히 중요하다.
PDF는 지금처럼 조사 자료·해설 형태로 유지하고, `recommended_title` **하나**에 대해서만 실제로
네이버 블로그에 붙여넣을 수 있는 초안을 별도 텍스트 파일로 만든다. 나머지 제목 후보는 초안을
쓰지 않는다(비용·시간 대비 효율).

- **분량**: 800~1200자 내외. 너무 짧으면 성의 없어 보이고, 너무 길면 안 읽는다.
- **어조**: 신문기사체가 아니라 "타겟 독자"(국장·미장·부업에 관심 있는 3040 직장인)와 같은
  또래가 옆에서 얘기해주듯 자연스러운 1인칭 블로그 말투("~해요", "~인데요"). "저도 회사
  다니면서 ~", "퇴근하고 ~" 같은 공감대 표현을 자연스럽게 섞는다. 섹션 내용을 그대로 복붙하지
  말고 새로 풀어써서 재구성한다.
- **키워드 배치**: `recommended_keyword`를 제목(이미 포함)과 도입부 첫 2~3문장 안에 1회, 본문
  중간에 자연스럽게 1~2회 더 넣는다. 억지로 여러 번 반복하지 않는다(키워드 스터핑은 검색
  노출에 오히려 불리함).
- **베끼지 않기**: 기사 문장을 그대로 옮기지 말고 반드시 직접 다시 풀어쓴다. `sources`의 사실
  관계만 참고하고 표현은 새로 쓴다.
- **구성**: 도입부(공감 가는 후킹 한두 문장) → 본문(섹션 내용을 재구성, 소제목 사용 가능) →
  마무리(요약 + 다음 글 예고나 구독 유도 한 문장) → 끝에 짧게 출처·면책 문구 한 줄(PDF와 같은
  취지, 길게 쓸 필요 없음).
- **저장**: 마크다운 기호 없이 순수 텍스트로 `.tmp/reports/economy_<report_type>_<날짜>_draft.txt`에
  저장한다 — 사장님이 그대로 복사해서 네이버 블로그 에디터에 붙여넣을 수 있어야 한다.
- 초안은 참고용 뼈대이지 최종본이 아니다. 그대로 발행하지 말고 한 번 훑어보고 손봐서 올리도록
  리포트에 짧게 안내한다.

## 실패했을 때 대응 원칙
- WebSearch 결과가 너무 적거나 신뢰하기 어려우면, 없는 내용을 채우지 말고 `data_note`에 그 사실을
  적고 다룰 수 있는 만큼만 다룬다. 실행 자체를 멈추지 않는다.
- PDF 생성(`economy_report_builder.py`) 자체가 에러로 실패하면 에러 내용을 쉬운 말로 사장님께
  설명한다. 같은 원인의 실패가 반복되면 이 문서와 `economy_report_builder.py`를 업데이트해서
  다음에는 자동으로 처리되게 한다.

## 사용하는 Tool
- `tools/economy_report_builder.py` — JSON 데이터를 받아 PDF로 조립. `python tools/economy_report_builder.py`만
  인자 없이 실행하면 샘플 데이터로 테스트 가능.
- `tools/naver_blog_search.py`의 `keyword_saturation()` — 제목·키워드 후보의 블로그 경쟁도 확인.
- `tools/naver_trend.py`의 `get_rising_keywords_by_segment()` — `practical_info` 슬롯의 주제·
  키워드 상승률 확인.
- WebSearch — 슬롯별 조사 대상 뉴스 검색 (별도 API 키 필요 없음, 에이전트 내장 기능).

## 알려진 한계 (사장님이 알아야 하는 것)
- 이 리포트는 투자자문이 아니라 정보 정리 자료다. PDF 하단에 면책 문구가 자동으로 들어가지만,
  블로그에 옮겨 쓸 때도 "투자 판단은 본인 책임" 같은 문구를 유지하는 게 안전하다.
- 실시간 웹 검색 기반이라, 검색 엔진에 아직 안 올라온 아주 최신 속보는 놓칠 수 있다.
- 18:30 미국장 리포트는 실제 개장 2~3시간 전이라 "예고편" 성격이다 — 개장 직전 최신 상황과는
  다를 수 있음을 사장님도 감안해야 한다.
- **제목·키워드 선정은 실제 월간 검색량 데이터가 아니라 대용 지표(블로그 경쟁도, 검색 관심도
  상승률, 보도 확산 정도)를 쓴다.** 더 정확한 숫자(월간 검색량, 예상 클릭당 단가 등)가 필요하면
  네이버 검색광고 API를 추가로 연동해야 하는데, 이건 별도 API 키 신청이 필요해서 사장님 확인
  후 진행해야 한다.
- 블로그 초안은 그대로 발행해도 되는 완성본이 아니라 시작점이다. 올리기 전에 한 번 훑어보고
  손보는 걸 권장한다.
