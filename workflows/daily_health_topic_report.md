# Workflow: 매일 건강 콘텐츠 트렌드 리포트

> 🎯 **북극성 목표 (모든 판단의 기준)**: 이 워크플로우의 모든 선택 — 카테고리 로테이션, 제목,
> 검색의도 분석, 초안 문체 — 은 전부 하나의 목표를 위해 존재한다: **하루 방문자 수를 늘려서
> 애드포스트 수익을 극대화하는 것.** 정보가 정확하고 유용한 것만으로는 부족하다 — 실제로
> 사람들이 검색해서 들어오고, 다시 찾아오게 만드는 게 최우선이다. [[economy_daily_reports]]도
> 같은 목표를 공유한다 (2026-08-09 확인).

## 목표
매일 아침 7시, 남녀노소 연령대x성별로 지금 뜨고 있는 건강 관련 검색 관심사를 파악해서 **서로
다른 키워드 2개**를 고르고, 각 키워드마다 (1) 그 키워드를 검색하는 사람들의 검색 의도 분석,
(2) 그 의도에 가장 잘 맞는 네이버 블로그 제목, (3) 타겟 독자 분석, (4) 메인 키워드 분석,
(5) 800~1200자 포스팅 초안까지 만들어서 PDF(요약+분석)와 초안 텍스트 파일 2개를 Claude
앱으로 전달한다. 최종 목표는 정보 전달 자체가 아니라 **하루 방문자 수를 늘려서 애드포스트
수익을 극대화**하는 것이다(북극성 목표 참고).

(참고: 처음에는 이메일 발송으로 설계했으나, 클라우드 실행 환경이 이메일 전송 방식(SMTP)을
지원하지 않아서 Claude 앱으로 직접 전달하는 방식으로 바꿨다. 사장님도 이메일이 꼭 필요하지
않다고 확인함.)

> ⚠ **왜 8개에서 2개로, "상승률 1위"에서 "날짜 로테이션"으로 바뀌었나 (2026-08-09 확인)**:
> 예전에는 상승률이 높은 카테고리를 최대 8개까지 뽑아서 보여줬는데, "노년건강"(고혈압관리)이나
> "남성건강"(전립선비대증) 카테고리가 거의 매일 상위권을 차지해서 실제로는 매일 비슷한 주제만
> 반복해서 나온다는 피드백을 받았다. 게다가 카테고리 안에서도 항상 목록의 첫 번째 키워드만
> 대표로 뽑아 쓰고 있었다(예: 노년건강 카테고리는 항상 "고혈압관리"만, 당뇨/골다공증/치매예방/
> 낙상예방은 한 번도 안 나옴). 그래서 상승률 랭킹 대신 11개 카테고리를 날짜 기준으로 강제
> 로테이션시켜 매일 다른 카테고리 2개, 그리고 카테고리 안의 구체적 키워드도 날짜별로 돌아가며
> 나오도록 `tools/run_daily_report.py`를 고쳤다. (참고: 원래 있던 "최근 14일 내 추천 키워드
> 제외" 방식은 `.tmp/`가 실행마다 초기화될 수 있어 완전히 믿을 수 없었다 — 날짜 로테이션은
> 별도 저장 없이도 항상 같은 결과를 내는 방식이라 더 안정적이다.)

## ⚠ 반드시 지킬 것 — 지어내지 않기 (건강 정보 버전)
제목·검색의도 분석·초안은 실시간 검색 트렌드 데이터를 근거로 하지만, 실제 문장은 에이전트가
직접 쓴다. 의료 정보를 다루므로 다음을 반드시 지킨다:
- 확신 없는 의학적 주장(정확한 유병률 수치, 특정 치료 효과 단정 등)을 지어내지 않는다.
  일반적으로 널리 알려진 상식 수준의 정보만 쓰고, 구체적 수치가 필요한데 확신이 없으면
  숫자 없이 정성적으로("많은 사람들이 겪는", "흔히 나타나는" 등) 서술한다.
- "당신은 OO입니다" 처럼 진단하듯 단정하지 않는다. "이런 증상이 있다면 OO일 수 있어요, 병원
  상담을 권해요"처럼 정보성 톤을 유지한다.
- 특정 약물·시술·제품(브랜드명 포함)을 추천하는 어조를 쓰지 않는다 — 의료광고법/약사법에
  저촉될 수 있다.
- 초안 끝에는 항상 "이 글은 정보 제공 목적이며 진단·치료를 대신하지 않습니다. 증상이 있다면
  병원 상담을 권합니다" 같은 문구를 짧게 남긴다.

## 언제 실행하나
- `schedule` 기능으로 매일 07:00 KST에 자동 실행되도록 등록되어 있음.
- 사장님이 "오늘 리포트 다시 보내줘" 처럼 수동으로 요청할 때도 같은 절차로 실행.

## 실행 방법 (Agent가 할 일)
1. `.env` 파일에 아래 값이 다 채워져 있는지 확인한다 (`.env.example` 참고).
   - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`
   - `YOUTUBE_API_KEY`
   - 하나라도 비어 있으면 실행하지 말고, 어떤 값이 빠졌는지 사장님께 알려준다.
2. `python tools/run_daily_report.py` 한 번 실행한다 (데이터 수집 전용 — PDF는 아직 안 만듦).
   - 내부적으로 하는 일: 데이터랩 검색어트렌드 조회 → 오늘 날짜 로테이션으로 카테고리 2개
     배정(카테고리 안의 구체적 키워드도 날짜별로 로테이션) → 블로그 포화도 확인 → 관련
     키워드로 유튜브 인기 영상 조회 → 후보 데이터를 JSON으로 저장.
3. `.tmp/logs/YYYY-MM-DD.log`를 읽는다. `CANDIDATES_READY: <경로>` 줄이 있으면 그 JSON을
   읽어서 다음 단계로 넘어간다. 실패했으면 "실패했을 때 대응 원칙" 참고.
4. **JSON의 `candidates` 각 항목(오늘 2개)마다 아래를 직접 작성한다** (아래 "제목·키워드
   선정 기준", "블로그 초안 작성 지침" 참고):
   - `search_intent`: 이 키워드를 검색하는 사람들이 실제로 뭘 원해서 검색했을지
   - `title`: 그 검색 의도에 가장 잘 맞는 네이버 블로그 제목 1개
   - `target_analysis`: 타겟 독자 분석 (연령·성별·상황을 구체적으로 — candidate의 segment
     데이터를 참고하되 그대로 베끼지 말고 왜 그런지 풀어쓴다)
   - `keyword_analysis`: 메인 키워드 분석 (candidate의 rising_pct·total_count를 근거로 왜
     이 키워드가 지금 다룰 만한지)
   - 800~1200자 포스팅 초안을 작성해서 `.tmp/reports/health_report_<날짜>_draft1.txt`,
     `_draft2.txt`로 각각 저장한다 (순서는 candidates 순서대로). 파일 맨 위에
     `search_intent`/`target_analysis`/`keyword_analysis`를 요약한 분석 블록을 먼저 적고,
     그 아래에 실제 초안을 쓴다 (economy_daily_reports.md와 같은 형식).
5. 위에서 채운 내용으로 `posts` 배열을 만들어 `candidates`를 대체하고 (다른 필드
   `segment_trends`/`youtube_top`/`blog_saturation`/`failed_sources`/`report_date`는 그대로
   유지), `.tmp/health_data/report_<날짜>.json`로 저장한다.
6. `python tools/report_builder.py <5번 json경로> .tmp/reports/health_report_<날짜>.pdf`를
   실행한다 (python이 없으면 python3).
7. 생성된 PDF와 초안 txt 파일 **셋 다**(PDF 1개 + 초안 txt 2개) 채팅 응답에 **직접 첨부**해서
   전달하고, 푸시 알림도 보낸다.
8. 결과를 사장님께 보고한다:
   - 성공: 오늘 키워드 2개와 제목 2개를 짧게 요약하고 PDF·초안 2개를 첨부.
   - 일부 실패(예: 유튜브 쿼터 초과로 이전 데이터 사용): 무슨 일이 있었는지 쉬운 말로 알려주고,
     PDF는 그래도 전달한다 (PDF에도 "갱신 실패" 표시가 남음).
   - 전체 실패(PDF 자체가 안 만들어짐): 에러 내용을 쉬운 말로 설명.

## 제목·키워드 선정 기준
제목·키워드는 방문자 수를 결정하는 가장 직접적인 지점이다 — 내용이 아무리 좋아도 검색에서
안 걸리면 방문자로 이어지지 않는다(북극성 목표 참고).
- `candidates`의 `reason`(상승률·블로그 경쟁도)을 `keyword_analysis`의 근거로 그대로 활용한다
  — 새로 조사할 필요 없이 `tools/run_daily_report.py`가 이미 계산해둔 데이터다.
- 검색 의도는 크게 두 갈래로 나눠서 생각한다: "이게 뭔지/내 얘기인지 확인하고 싶다"(개념·자가진단형)
  와 "지금 뭘 해야 하는지 알고 싶다"(관리법·실천형). 이 키워드가 둘 중 어느 쪽에 가까운지
  판단해서 제목에 반영한다 (예: "OO 자가진단", "OO 관리법", "OO 뜻").
- 제목은 막연하게 짓지 않는다 — `search_intent`에서 정리한 의도가 제목만 보고도 짐작될 정도로
  구체적이어야 한다.

## 블로그 초안 작성 지침
초안의 역할은 정보 전달이 아니라 "검색해서 들어온 사람이 끝까지 읽고, 다음에도 이 블로그를
찾아오게 만드는 것"이다(북극성 목표 참고) — 그래서 도입부 후킹과 키워드 배치가 특히 중요하다.
- **분량**: 800~1200자 내외.
- **어조**: 신문기사체·의학논문체가 아니라 자연스러운 1인칭 블로그 말투("~해요", "~인데요").
  `target_analysis`에서 정한 독자가 편하게 읽을 수 있는 눈높이로 쓴다.
- **키워드 배치**: 메인 키워드를 제목(이미 포함)과 도입부 첫 2~3문장 안에 1회, 본문 중간에
  자연스럽게 1~2회 더 넣는다. 억지로 반복하지 않는다(키워드 스터핑은 검색 노출에 불리함).
- **구성**: 도입부(공감 가는 후킹) → 본문("OO가 뭔지" 쉬운 설명 + 관리법·실천 팁, 소제목
  활용 가능) → 마무리(요약 + 다음 글 예고나 구독 유도 한 문장) → 위 "지어내지 않기"에서 정한
  면책 문구 한 줄.
- **저장**: 마크다운 기호 없이 순수 텍스트로 저장한다 — 사장님이 그대로 복사해서 네이버 블로그
  에디터에 붙여넣을 수 있어야 한다.
- 초안은 참고용 뼈대이지 최종본이 아니다. 그대로 발행하지 말고 한 번 훑어보고 손봐서 올리도록
  안내한다.

## 결과물 확인 위치
- PDF: `.tmp/reports/health_report_YYYY-MM-DD.pdf`
- 블로그 초안(2개): `.tmp/reports/health_report_YYYY-MM-DD_draft1.txt`,
  `health_report_YYYY-MM-DD_draft2.txt`
- 데이터 수집 결과(1단계, Tool 산출물): `.tmp/health_data/candidates_YYYY-MM-DD.json`
- 최종 리포트 데이터(2단계, Agent가 posts를 채운 결과): `.tmp/health_data/report_YYYY-MM-DD.json`
- 실행 로그: `.tmp/logs/YYYY-MM-DD.log`
- 추천 이력(참고용 기록 — 카테고리 선정은 이제 날짜 로테이션이라 이 파일에 의존하지 않음):
  `.tmp/recommendation_history.json`
- 각 데이터 소스의 마지막 성공 결과 캐시: `.tmp/cache/`

## 실패했을 때 대응 원칙
- 네이버 데이터랩/유튜브 API 호출이 실패하면: 마지막으로 성공했던 캐시 데이터로 대체하고,
  리포트 상단에 "오늘 일부 데이터 갱신 실패" 문구를 넣는다. 실행 자체는 멈추지 않는다.
- API 키/비밀번호 자체가 잘못됐거나 만료된 경우: 유료 API 재시도로 크레딧을 낭비하지 않도록,
  같은 실행을 무한정 재시도하지 말고 사장님께 먼저 확인받는다.
- `report_builder.py` 실행(6번 단계) 자체가 에러로 실패하면(예: posts 필드 누락) 에러 내용을
  쉬운 말로 설명하고, JSON에 빠진 필드가 있는지 먼저 확인한다.
- 같은 원인의 실패가 반복되면, 이 워크플로우 문서에 원인과 대응 방법을 추가해서 다음에는
  같은 문제가 자동으로 처리되게 한다.

## 사용하는 Tool
- `tools/naver_trend.py` — 데이터랩 검색어트렌드 (연령대x성별 상승 키워드)
- `tools/naver_blog_search.py` — 블로그 검색 (경쟁도/포화도 참고자료)
- `tools/youtube_trend.py` — 유튜브 인기 건강 콘텐츠
- `tools/run_daily_report.py` — 위 3개를 순서대로 실행해 오늘의 후보 데이터(JSON)를 만드는
  1단계 오케스트레이터. PDF는 만들지 않는다 — 검색의도 분석·제목·초안 작성은 사람(에이전트)이
  직접 해야 하는 영역이기 때문 (2026-08-09부터 이렇게 나뉨).
- `tools/report_builder.py` — 2단계. 에이전트가 posts를 채운 JSON을 받아 최종 PDF로 조립한다.
  `python tools/report_builder.py <json경로> <pdf경로>` (인자 없이 실행하면 샘플 데이터로 테스트
  가능). [[economy_daily_reports]]의 `economy_report_builder.py`와 같은 패턴.

## 알려진 한계 (사장님이 알아야 하는 것)
- 네이버 블로그의 실제 "인기 포스팅 순위"(조회수/좋아요)는 공식 API로 볼 수 없음. 지금은
  "검색 관심도가 얼마나 올랐는지"로 대체하고 있음 — 실제로 이미 많이 다뤄진 주제인지는
  블로그 포화도(게시물 수)로만 간접 추정.
- 예상 클릭당 단가(CPC)나 광고 경쟁 강도는 지금 로직에 없음. 필요하면 네이버 검색광고 API를
  추가로 연동해야 함 (별도 신청 필요, 사장님 확인 후 진행).
- 유튜브 검색은 하루 호출 수를 최대 8회로 제한해뒀음(쿼터 절약). 카테고리를 2개만 다루는
  지금은 실제로는 하루 2회만 호출됨 — 쿼터 여유가 더 생긴 셈.
- 카테고리 2개는 11개 카테고리를 날짜로 순서대로 도는 방식이라, 완전히 한 바퀴 도는 데
  대략 5~6일 걸린다. "오늘 상승률이 가장 높은 카테고리"를 놓칠 수 있다는 뜻이지만, 그 대신
