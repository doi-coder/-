# Workflow: 매일 건강 콘텐츠 트렌드 리포트

## 목표
매일 아침 7시, 남녀노소 연령대x성별로 지금 뜨고 있는 건강 관련 검색 관심사를 파악하고,
유튜브에서 화제인 건강 콘텐츠를 참고해서, 사장님이 오늘 네이버 블로그에 포스팅하면 좋을
주제를 데이터 기반으로 추천한 브랜드 PDF 리포트를 만들어 사장님 네이버 메일로 보낸다.

## 언제 실행하나
- `schedule` 기능으로 매일 07:00 KST에 자동 실행되도록 등록되어 있음.
- 사장님이 "오늘 리포트 다시 보내줘" 처럼 수동으로 요청할 때도 같은 절차로 실행.

## 실행 방법 (Agent가 할 일)
1. `.env` 파일에 아래 값이 다 채워져 있는지 확인한다 (`.env.example` 참고).
   - `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`
   - `YOUTUBE_API_KEY`
   - `GMAIL_ADDRESS`, `GMAIL_APP_PASSWORD`
   - `REPORT_RECIPIENT_EMAIL` (사장님 네이버 메일)
   - 하나라도 비어 있으면 실행하지 말고, 어떤 값이 빠졌는지 사장님께 알려준다.
2. `python tools/run_daily_report.py` 한 번 실행한다. (이 한 줄이 아래 내부 단계를 전부 처리함)
   - 내부적으로 하는 일: 데이터랩 검색어트렌드 조회 → 세그먼트별 상승 카테고리 선정 →
     최근 14일 내 이미 추천한 키워드는 제외 → 블로그 포화도 확인 → 관련 키워드로 유튜브
     인기 영상 조회 → PDF 리포트 생성 → Gmail로 사장님 네이버 메일에 발송 → 로그 저장.
3. `.tmp/logs/YYYY-MM-DD.log`를 읽어서 성공/실패 여부를 확인한다.
4. 결과를 사장님께 보고한다:
   - 성공: "오늘 리포트 발송 완료, 추천 주제 N개" 정도로 짧게.
   - 일부 실패(예: 유튜브 쿼터 초과로 이전 데이터 사용): 무슨 일이 있었는지 쉬운 말로 알려주고,
     리포트 자체는 정상 발송됐다는 것도 함께 알려준다 (PDF에도 "갱신 실패" 표시가 남음).
   - 전체 실패(메일도 못 감): PDF가 `.tmp/reports/`에 남아있다는 것과, 에러 내용을 쉬운 말로 설명.

## 결과물 확인 위치
- PDF: `.tmp/reports/health_report_YYYY-MM-DD.pdf`
- 실행 로그: `.tmp/logs/YYYY-MM-DD.log`
- 추천 이력(중복 방지용): `.tmp/recommendation_history.json`
- 각 데이터 소스의 마지막 성공 결과 캐시: `.tmp/cache/`

## 실패했을 때 대응 원칙
- 네이버 데이터랩/유튜브 API 호출이 실패하면: 마지막으로 성공했던 캐시 데이터로 대체하고,
  리포트 상단에 "오늘 일부 데이터 갱신 실패" 문구를 넣는다. 실행 자체는 멈추지 않는다.
- 메일 발송이 실패하면: PDF는 이미 로컬에 생성되어 있으니 그대로 두고, 원인을 로그에 남긴다.
  같은 문제가 반복되면(예: Gmail 앱 비밀번호 만료) 사장님께 재발급을 요청해야 한다.
- API 키/비밀번호 자체가 잘못됐거나 만료된 경우: 유료 API 재시도로 크레딧을 낭비하지 않도록,
  같은 실행을 무한정 재시도하지 말고 사장님께 먼저 확인받는다.
- 같은 원인의 실패가 반복되면, 이 워크플로우 문서에 원인과 대응 방법을 추가해서 다음에는
  같은 문제가 자동으로 처리되게 한다.

## 사용하는 Tool
- `tools/naver_trend.py` — 데이터랩 검색어트렌드 (연령대x성별 상승 키워드)
- `tools/naver_blog_search.py` — 블로그 검색 (경쟁도/포화도 참고자료)
- `tools/youtube_trend.py` — 유튜브 인기 건강 콘텐츠
- `tools/report_builder.py` — PDF 조립
- `tools/mailer.py` — Gmail SMTP 발송
- `tools/run_daily_report.py` — 위 5개를 순서대로 실행하는 오케스트레이터 (매일 이거 하나만 실행하면 됨)

## 알려진 한계 (사장님이 알아야 하는 것)
- 네이버 블로그의 실제 "인기 포스팅 순위"(조회수/좋아요)는 공식 API로 볼 수 없음. 지금은
  "검색 관심도가 얼마나 올랐는지"로 대체하고 있음 — 실제로 이미 많이 다뤄진 주제인지는
  블로그 포화도(게시물 수)로만 간접 추정.
- 예상 클릭당 단가(CPC)나 광고 경쟁 강도는 지금 로직에 없음. 필요하면 네이버 검색광고 API를
  추가로 연동해야 함 (별도 신청 필요, 사장님 확인 후 진행).
- 유튜브 검색은 하루 호출 수를 8회로 제한해뒀음(쿼터 절약). 더 넓게 보고 싶으면 늘릴 수 있지만
  쿼터 소진 위험이 커짐.
